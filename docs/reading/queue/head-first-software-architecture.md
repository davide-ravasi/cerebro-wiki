Companion to the authors' deeper **Fundamentals of Software Architecture** — same ideas, lighter pace and visuals.

# What it covers (high level)

- **Architecture vs design** — roles and boundaries
- **Architectural thinking** — tradeoffs, not just patterns
- **Code, components, architectural styles** — common styles with examples
- **Relationship to implementation** — how structure shows up in real systems

Not a frontend book; not distributed-data depth (that's **DDIA**).

# Fit with current work

| Project / study | Why this book |
|---------------|----------------|
| **tracking-ds** | Articulate MVP choices (static JSON, CI pipeline, scan vs dashboard) as architectural tradeoffs |
| **Presentations** | Framework for “what we decided and why” |
| **DDIA** | Different lens — system shape vs data/replication/consensus |
| **Career** | Bridge toward staff/architect conversations without starting on *Fundamentals* |

# Notes

- Senior readers: expect Head First pace — **skim** sections that feel obvious; slow down on tradeoff chapters
- If hungry for more after: **Fundamentals of Software Architecture** (same authors, denser)
